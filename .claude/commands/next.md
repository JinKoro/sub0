Взять issue `#$ARGUMENTS` из репозитория `JinKoro/sub0`, создать ветку от свежего `master` и начать делать задачу.

## Шаги

1. Проверить аргумент: `$ARGUMENTS` должен быть целым положительным числом. Если нет — сообщить пользователю и остановиться.
2. Параллельно:
   - `git status --porcelain` — проверить чистоту рабочего дерева.
   - `git rev-parse --abbrev-ref HEAD` — текущая ветка.
   - `gh issue view $ARGUMENTS -R JinKoro/sub0 --json number,title,body,state,labels,url` — получить issue.
3. Если рабочее дерево грязное — **остановиться**, попросить пользователя сначала закоммитить через `/go` (или сделать stash вручную). Ничего не переключать.
4. Если `gh issue view` вернул ошибку (issue не существует / нет доступа) — сообщить и остановиться.
5. Если `state` issue равен `CLOSED` — предупредить пользователя и спросить, продолжать ли. Без подтверждения — остановиться.
6. Переключиться на `master` и обновить:
   - `git checkout master`
   - `git pull --ff-only origin master`
   - Если pull упал (расхождение, конфликт) — остановиться, не ломать историю.
7. Создать/переключиться на ветку `$ARGUMENTS`:
   - Если ветка уже существует локально (`git rev-parse --verify $ARGUMENTS` вернул ОК) — `git checkout $ARGUMENTS`, без `-b`.
   - Иначе — `git checkout -b $ARGUMENTS`.
8. Вывести краткое summary: номер и title issue, URL, имя ветки.
9. Прочитать тело issue (`body` из шага 2). Если задача требует UI/архитектурных решений — перед кодом перечитать релевантные `ai/ctx-*.md` (см. `AGENTS.md`). Дальше — действовать по правилам проекта (`AGENTS.md`): без выдуманных имён, без преждевременных абстракций, по roadmap.
10. Предложить пользователю план реализации (или сразу начать, если задача тривиальная и план очевиден).
