description: Закоммитить все изменения с префиксом "#<branch>:", запушить и открыть PR со ссылкой на issue и её лейблами
---

Закоммить все локальные изменения, запушь ветку в origin, открой PR на `master` с привязкой к issue и теми же лейблами.

## Шаги

1. Параллельно: `git status`, `git diff` (staged + unstaged), `git log --oneline -10`, `git rev-parse --abbrev-ref HEAD`.
2. Если изменений нет (`git status` чистый) и коммит уже запушен — перейти сразу к шагу 11 (PR), не пытаться коммитить. Если изменений нет и коммитить нечего, и PR уже существует — сообщить пользователю и закончить.
3. Перепроверь `git status` на предмет случайно попавших секретов (`.env`, ключи, токены). Если что-то такое есть — НЕ коммитить, спросить пользователя.
4. Сформировать короткое (≤ 70 символов) описание изменений на русском в одном предложении, без точки в конце, без emoji. Описание должно отражать ЦЕЛЬ изменений, а не их форму. Стиль — как в `git log` проекта.
5. Сформировать commit message:
   - Если имя ветки — целое число (например `8`, `12`): `#<branch>: <description>`.
   - Иначе: просто `<description>`, без префикса.
6. `git add -A` — застейджить все изменения (пользователь явно просит "все изменения").
7. `git commit` через HEREDOC с сформированным message. Без `Co-Authored-By` футера. Без `--amend`. Без `--no-verify`.
8. Если pre-commit hook упал — диагностировать и исправить причину, потом создать **новый** коммит (не амендить).
9. `git status` — убедиться что коммит создался.
10. Push:
    - Проверить upstream: `git rev-parse --abbrev-ref --symbolic-full-name @{u}`.
    - Если upstream нет — `git push -u origin <branch>`.
    - Иначе — `git push`.
    - Никогда не использовать `--force` / `--force-with-lease` без явной просьбы пользователя.
11. Pull request:
    - Если имя ветки **не** целое число — пропустить шаг, перейти к 12.
    - Иначе — пусть `N = <branch>` (номер issue).
    - Проверить, есть ли уже PR для этой ветки: `gh pr list -R JinKoro/sub0 --head <branch> --state open --json number,url --jq '.[0]'`.
      - Если PR уже есть — взять его URL, перейти к шагу 12.
    - Получить лейблы issue: `gh issue view <N> -R JinKoro/sub0 --json labels --jq '[.labels[].name] | join(",")'`.
      - Если команда упала (issue не существует) — создать PR без `--label`, без `Closes`, без префикса.
    - Создать PR:
      - `--base master`, `--head <branch>`.
      - `--title` = ровно тот же текст, что в commit message (то есть `#<N>: <description>`).
      - `--body` = `Closes #<N>` (одна строка, без блоков Summary / Test plan).
      - `--label` для каждого лейбла из issue.
    - Команда (пример, лейблы добавляются повторными `--label`):
      ```
      gh pr create -R JinKoro/sub0 \
        --base master --head <branch> \
        --title "<commit subject>" \
        --body "Closes #<N>" \
        --label "<l1>" --label "<l2>" ...
      ```
12. Вывести одну строку summary: что закоммитили, куда запушили и URL PR (или URL ветки, если PR не создавали).
