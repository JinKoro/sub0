# Sub0 — Roadmap

Sub0 — веб-сервис учёта подписок: дашборд, аналитика, календарь
списаний, уведомления. Web-first (Next.js + PWA-манифест), нативное
мобильное — v2.

Живой документ: при добавлении / переносе фич между версиями —
обновлять здесь, а не в чате.

---

## Концепция

### Лендинг (`apps/web`, route group `(marketing)`)

Хедер: Продукт, Инструменты (v2), Ресурсы (Блог/FAQ — v1.1; Отзывы /
Портал идей / Roadmap — v2), Тарифы. Языки: ru / en. Кнопки
Login/Register; для залогиненных — «В дашборд».

Контент страницы: hero, фичи, отзывы, тарифы, футер.

### Дашборд (`(app)`)

Блоки и порядок ввода в продукт:

1. **Подписки** — добавление вручную (MVP), AI-парсинг выписки (v1.1).
2. **База сервисов** — топ-50 ручным импортом (MVP), 500+ с иконками
   и ссылками на отмену (v1.1).
3. **Аналитика** — totals + календарь (MVP), графики Recharts (v1.1).
4. **Проекты** — несколько дашбордов с переключением (MVP). На
   регистрации создаётся дефолтный «Personal»; пользователь может
   создать дополнительные. Все подписки / категории / история
   списаний scoped по `project_id`. В хедере — switcher текущего
   проекта + опция «Все проекты» (агрегированная аналитика).
   Team-аккаунты по проектам — v2.

### Логин

- Email/пароль — MVP.
- OAuth (Google, Yandex) + 2FA + быстрая авторизация — v2.

### Настройки

- **Аккаунт** — имя, email, аватар (≤ 2MB), timezone (MVP).
- **Тарифы и оплата** — текущий тариф, привязанная карта (MVP).
- **Уведомления** — email (MVP); Telegram + Web Push (v1.1).
- **Безопасность** — смена пароля (MVP); управление сессиями + 2FA
  (v2).

### Профильное меню

Иконка профиля → настройки аккаунта, тарифы, переключатель темы,
ссылка на сайт, выход.

## ✅ MVP (4 недели)

### Лендинг

- Хедер с навигацией, i18n (ru/en), login/register.
- Hero / фичи / тарифы / футер.
- PWA: `manifest.json` + `apple-touch-icon` для add-to-home на iOS.

### Авторизация

- **Регистрация — двухшаговая.** Шаг 1: `name + email + consents`
  → customer `state = CREATED` (без пароля) + дефолтный project
  `Personal` + одноразовая ссылка `/registration/complete?token=`
  на email (через `mail_outbox`). Шаг 2: по ссылке юзер задаёт
  пароль → `state = ACTIVE` + выдача токенов. Пароль в DTO
  регистрации **не** передаётся.
- Email + пароль (`argon2id`).
- JWT access 15m + refresh 90d с ротацией (`httpOnly + Secure +
SameSite=Lax` cookie). Юзер не перезаходит вручную — но это **не**
  «сессия без expiry»: токены прозрачно обновляются на каждом
  запросе. Access-JWT дублируется в `sub0_session` cookie
  (`Path=/`) для серверного гейта роутов кабинета.
- Email verification обязательна **до первой оплаты**.
- Удаление аккаунта (soft → hard через 30 дней) — требование 152-ФЗ
  / GDPR.

### Дашборд — ядро

- Добавление подписки вручную: название, сумма, валюта (RUB / USD /
  EUR / BYN), периодичность, категория, дата ближайшего списания.
- Список подписок с иконками **топ-50 сервисов** (захардкоженный seed).
  Кастомные подписки (без `serviceId`) могут иметь собственный
  `iconUrl`; иначе UI показывает initials.
- Totals в месяц / год **по валютам отдельно** + опциональная
  конвертация в основную валюту юзера.
- Курсы валют: суточный pull с ЦБ РФ (`@nestjs/schedule`), кеш
  в Postgres. При недоступности — последний валидный + `stale_at`.
- Календарь списаний + лента «ближайшие 30 дней».
- Редактирование / удаление подписки.
- История списаний.
- **Статусы подписки:** `ACTIVE`, `PAUSED`, `CANCELLED` (работает до
  `nextBillingDate`, потом cron переводит в `ARCHIVED`), `ARCHIVED`.
  `PAUSED` исключается из totals и календаря; `CANCELLED` остаётся
  в календаре до даты архивации.
- **Проекты:** см. Концепцию выше. На регистрации создаётся
  «Personal»; CRUD проектов; switcher в хедере; опция «Все проекты»
  для агрегированной аналитики.
- **Триал-поля в схеме (UI — v1.1):** `trialEndsAt` уже хранится
  в MVP-миграции, чтобы v1.1 (маркер триала в UI + отдельная фича
  «отмена до конца триала») не требовала ALTER.

**Time zones:** даты списания в `timestamptz` (UTC), отображение в
`user.timezone` (IANA). Email-нотификации планируются с учётом
TZ юзера, иначе будут приходить в 3 ночи.

### Настройки

- Имя, email, аватар, timezone (дефолт — IANA из браузера).
- Смена пароля.
- Email-нотификации: за N дней до списания, дефолт 3 дня.

### Фримиум

- Free: до 5 подписок.
- Paid: безлимит.

### Оплата (автосписание)

- СБП / T-Bank / Сбер для РФ. BePaid для РБ.
- Только токены провайдеров — карт у нас нет.
- **Зависимость:** реальное автосписание возможно только после
  юрлица + договора с банком-эквайером. До этого — mock-провайдер
  для дев-окружения.

## 🔜 v1.1 (месяц 2–3)

### Контент

- Блог.
- FAQ.

### Нотификации

- Telegram-бот: link-flow через deep-link с одноразовым nonce; очередь
  отправки; шаблоны через общий i18n с email.
- Web Push (VAPID), per-device subscriptions.

### Дашборд

- AI-парсинг выписки: PDF → LLM **транзитом** (у нас не хранится).
  Поддержка 5–10 банков (СберБанк, Тинькофф, Альфа, Райффайзен,
  Открытие, Belarusbank, Priorbank, MTBank, БСПБ, Беларусбанк-Альфа).
  **Закладывай неделю** только на промпт-инжиниринг и форматы
  выписок.
- База 500+ сервисов с иконками + ссылками на отмену.
- Пробный период у подписок: маркер в календаре + отдельный блок
  «триалы на отмену» в дашборде. Поле `trialEndsAt` уже в схеме
  с MVP — UI/нотификации добавляются здесь.
- Графики аналитики (Recharts).
- Кастомные категории подписок: CRUD + отдельная под-страница
  в кабинете («Свои категории»). Таблица `category_custom` в MVP
  уже есть, но UI и эндпоинты — здесь.
- **Редактор истории списаний** (`billing_history`): просмотр,
  правка и удаление отдельных транзакций подписки. Сейчас MVP
  делает backfill при создании, но `firstBillingDate` после
  создания иммутабельно (см. `ctx-business-logic.md`). Редактор
  снимает это ограничение — можно будет менять стартовую дату
  и регенерировать историю, либо точечно править записи без
  сдвига даты. Связанные эндпоинты `GET/POST/DELETE
  /subscriptions/:sku/history` появятся вместе с UI.

### Оплата

- T-Bank / Сбер как дополнительные методы (после первичного провайдера
  в MVP).

## Открытые вопросы (требуют решения до старта)

- **Юрлицо для эквайеров** — статус? Без этого автосписание не
  запустить → MVP едет на mock-провайдере.
- **Хостинг** — Vercel (web) + что под Nest? VPS / Railway / Render
  / Fly?
- **Email-провайдер** — резидент РФ/СНГ (хостинг и адресаты в РФ),
  с DKIM/SPF/DMARC и SMTP relay. Конкретный сервис не выбран.
  Resend / Postmark / SES не подходят — нужен российский / СНГ
  поставщик. До решения — в dev стоит MailHog, прод-ключи добавим
  при выборе.
- **S3-совместимое хранилище для аватаров** — облако или self-hosted
  MinIO?
- **Cron для курсов** — `@nestjs/schedule` внутри `apps/api` или
  отдельный воркер?
